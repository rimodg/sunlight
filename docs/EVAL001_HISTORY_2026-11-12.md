## Code at the time

At c515bd8, both evaluators import `get_clean_contracts` from doj_validation.py.
That function selects the comparison sample with `ORDER BY RANDOM() LIMIT ?`.
The evaluator's NumPy seed and per-contract scoring seeds do not seed SQLite's
random ordering. Two executions with --seed 42 can therefore evaluate different
negative populations while recording identical CLI settings.

Commit `99991fafb628e4182273a84b063c907bda895cc6`, April 13, replaced that selection
with `ORDER BY c.contract_id` followed by
`random.Random("sunlight-doj-v1").sample(...)`. The old reports predate this fix.
The explicit clean=200 protocol bypasses later automatic sample-size selection.
The scoring-path differences inspected since c515bd8 are citation handling,
SQL allowlist hardening and a profile deprecation comment, not a change needed
to reproduce the old report's scores.
