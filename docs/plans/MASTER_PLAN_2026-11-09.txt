SUNLIGHT: The Master Plan
1. The end goal
One instrument that reads the whole chain of public value, from the person who digs the ore or grows the bean to the institution that pays for the finished thing, checks each joint against the law that governs it, counts who was left out in the institutions' own published figures, and hands the reading to the body with power to act.
It is finished when five things are true at once.
It watches on its own. Captures real public sources on a schedule, resolves every party, runs every rule across whole populations, and reports what changed since last time. Nobody runs it by hand.
Every finding carries its law. Not a score. The provision in the institution's own words, the party who owed the missing piece, and the body whose mandate covers it.
The person is in the ledger. The producer's share where law fixes it, the documented need where institutions publish it, in the same graph as the money, with nothing computed between them.
It checks conditions before payment. Where an institution has written a condition into its own contract and delegated the check, the system verifies it and the payment waits if it fails. The institution always decides and can always override.
Anyone can check it. Deterministic, no model in the analytical path, every finding reproducible by hand from documents anyone can download.
What it is not: an enforcer, an accuser, a replacement for institutions, or a proprietary standard. The standard is the published invariants. SUNLIGHT is one implementation that passes them.
2. What exists today
Read from the public repository, 9 November 2026. 232 commits, 10 open pull requests, no releases, no tags.
On main. The analyser. Sixteen-stage pipeline across five sides: procurement verification (statistical engine, rule engine with sixteen rules across five layers, evidence gate), delivery verification with twelve rules, cross-contract triage, recovery tracking with the Absence Ledger, and corroboration against six evidence classes. Four jurisdiction profiles: US federal, UK central government, World Bank international, France. A REST API with roughly seventy-five routes. A dashboard. The charter and the institutional review brief.
Not on main. The four organs of the watch. watch_identity, watch_journal, watch_capture, watch_examination and watch_engine exist only on milestone-1a-rebuild at commit 3566fd6. The twelve watch_* files that do sit on other branches are globe layers for arms, trade, conflicts and materials, not the engine. The engine was built on 26 October, reported complete, never pushed, and lost with its sandbox. The rebuild is the second attempt.
Branches that matter. main, the analyser. milestone-1a-rebuild, the four organs plus the installer and health reporting. milestone-1a, the frozen acceptance evidence. codex/sunlight-hosted-access at 87d6bae, which is what was last published for hosting and predates every fix.
What is deployed. An instance on Render running code from before the October remediation. It has no admission boundary, stores records and uploaded originals in shared SQLite with retrieval routes, and its only access control is one shared password that is absent unless configured. The recommendation to take it offline after preserving its state was made on 26 October and has not been carried out.
What the numbers actually say. The README still reports 1,889 tests and the detection figures 33.3 percent precision, 100 percent recall, 9.0 percent false positive rate. The measured backend suite on 2 November was 2,487. The recall figure rests on nine synthesized positive price examples, 200 presumed-negative comparisons and one excluded case, not on real prosecuted outcomes. That correction was made in the October audit and is stated in the review brief, but the README's design principles still read "100% DOJ recall is the institutional credibility floor."
The reference database sits outside Git on one laptop, 169,349,120 bytes, SHA-256 recorded. Without it the floor cannot be reproduced anywhere.
3. Where we were when this paused
A four-milestone finish order, agreed before the three-part brief arrived. Scope was frozen deliberately: no new categories, sources or features until all four passed.
1. Population screening. The engine captures both sources on a schedule and screens the whole population, unattended.
2. Ranking and packets. Findings ranked by how many independent dimensions agree, each with a packet reproducible by replay.
3. The interface as the system. Every screen a direct view of the journal. Any value that cannot be traced to a journal record fails the build.
4. Deployment. Old instance offline, verified build deployed, real build identity reported.
What had been achieved. On 27 October, on live public data, the method was proved: 27,985 UK award releases across ten months yielded 4,489 distinct suppliers carrying Companies House identifiers; against 202 organisations reporting to IATI under the same registry, 20 matched on normalised identifier. Names differed on nearly every match, and one publisher's organisation name field contained a file path. The identifier matched regardless. One award notice contained a person's email address in the supplier name field, and the protection rule refused it before it entered the repository.
Where it stopped. Milestone 1A, making the watch installable as a background service on a Mac, is built and pushed but unverified. The install requires Python 3.12 and the Mac has only 3.14. The attempt to install it failed because one download host would not resolve. That is the precise point of interruption: one interpreter and a network problem.
What the pause revealed. The build environment has no network access, so every acceptance run attempted there died at the proxy before reaching origin. Work must run where the sources are reachable. And twice in two weeks, completed work was lost because it existed only in a sandbox. The rule that fixed it is now first in every work order: push to a branch on origin immediately after the first commit, before writing any report.
4. The eight layers, and what is missing in each
Each layer below states what exists, what is missing, and what proof closes the gap. They are ordered by dependency: nothing in a later layer works without the ones above it.
4.1 The engine
Exists. The analyser, mature and tested. Rules with citations, the evidence gate, delivery verification, recovery, corroboration, four jurisdiction profiles, roughly 2,500 passing tests.
Missing. Three defects named in the October audit and not yet closed. The README's claims do not match measurement. The reference database lives on one laptop, so the floor is unreproducible anywhere else. And /version reports unversioned because the production image does not copy Git metadata, which means the system cannot say which build is answering.
Proof. Floor reproduced on a machine that is not the developer's, README numbers matching a run someone watched, and a build that can state its own identity.
4.2 Identity
Exists. On the rebuild branch: identity resolved only on cited identifiers, conflicts held as conflicts, unresolved as a first-class state, order-independent by construction. The normalisation rule for Companies House identifiers, padding numeric forms to eight digits and keeping prefixed forms as published.
Missing. The registry is per-category, not yet the join across categories. A hub that appears as a gold destination, an arms recipient and a contractor base is still three separate nodes. Beneficial ownership is absent entirely, which is the gap that makes the independence invariant weak.
Proof. One party resolved across two categories from two differently shaped sources into a single subject, with every link traceable to a cited identifier.
4.3 Capture and the watch loop
Exists. On the rebuild branch: scheduled capture with a frozen source policy, no raw bodies retained, failed attempts kept as receipts so the last good observation survives, cursors that resume, and a loop that re-reads when something changes. A response containing email-shaped content is refused in full before persistence. The freeze rule holds: the engine reads only frozen captures at a stated moment, so a finding reproduces byte for byte.
Missing. It has never captured a real public source. Both adapters are unvalidated against live endpoints. Rate limiting is handled but untested at scale, and the UK portal caps at 100 records a page with a strict limiter. There is no coverage declaration travelling with each record, so a finding cannot yet say whether it was computed on complete input. And the service is not installed anywhere, so nothing runs unattended.
Proof. An unattended scheduled run that captures two real sources, accumulates a journal across days, and reports a genuine published change it noticed on its own.
4.4 The invariants
Exists. Ten families drafted: value conserved, declarations mirrored, capacity respected, events in order, parties independent, procedure fitting value, price within envelope, records complete, recipients eligible, chain unbroken. Each with its formula, refusals, and the World Bank sanctionable practice it can indicate.
Missing. None are implemented. The conservation engine does not exist: no typed quantities with units, no exact decimal arithmetic, no refusal to subtract across units without a cited conversion, no tolerance tables with sources. The sixteen rules on main are procurement-specific and do not generalise. And the parameters that make feasibility arithmetic rather than opinion, yields per hectare, payloads, recovery rates, are not sourced anywhere.
Proof. One invariant computed end to end on real data, where the finding shows its equation, its terms with units and sources, its tolerance with a citation, and the residual before and after that tolerance. A reader redoes it on paper and gets the same number.
4.5 The law layer
Exists. Per-rule citation selection, fixed in September after every procurement finding was carrying the whole profile dictionary, including bribery articles, onto a single-bidder award. Four jurisdiction profiles with their own citation sets. The World Bank's five sanctionable practices and restitution provision read from source.
Missing. The conventions themselves. The ILO instruments, the Convention on the Rights of the Child, the UN Guiding Principles, the OECD Guidelines and the national enforcement laws are named in the argument paper and marked unverified. None has been read from its own text, and none is attached to a rule. The three anchors each invariant needs, binding provision, acting body, recovery route, exist for the World Bank only.
Proof. A findings packet where every line quotes its provision in the institution's own words, names the body whose mandate covers it, and states how money comes back, with the binding status of each instrument stated plainly: binds states, binds companies, or binds nobody.
4.6 The human layer
Exists. The Absence Ledger, which reads an institution's own programme document and states what a diversion left unfunded, cited, never estimated. The framing gates that keep "at risk" from becoming "deprived" before the institution confirms. The protection line: aggregate only, no personal data, enforced at the capture boundary.
Missing. The producer share, which is the strongest thing available and is not built. Ghana's law fixes at least 70 percent of export value to farmers; they received 63.9 percent; both numbers are published by the same institution. That is a ratio with a legal floor, computable today, needing no new agreement. Also missing: the Need Ledger generalised from the Absence Ledger, and adapters for funding and food-security data.
Proof. The producer share computed for one commodity in one country, with the three numbers, the legal floor, and the gap, each cited. Where a number is missing, the finding names the party who failed to publish it.
4.7 The interface
Exists. A working globe with layers for procurement, trade, materials, arms and conflict. Figures carry their year and basis. "Not analyzed, 0 records" sits where a fake score would normally go. A footer showing coverage per layer. The line "Decision support. Human authority. Documented limits."
Missing. It is a view onto data, not a view of the system. Three headline figures of different years and bases sit side by side as if comparable. Layer vintages span 2022 to 2026 with the dates only in the legend. A robot avatar sits beside the claim that no model takes part in a finding. And there is no view of a subject over time, which is the whole point of a watch.
Proof. A test that fails the build when any value on any screen cannot be traced to a journal record, and three views that work: the population with its coverage, one subject over time, and a finding with click-through to every source document.
4.8 The payment layer
Exists. Nothing. This layer has never been built and is not designed beyond the brief.
Missing. Everything, and it is worth being precise about what "everything" means, because this is the layer most likely to be underestimated.
The narrow version is: an institution writes a condition into its own contract, delegates the check, and SUNLIGHT verifies whether the condition is met before disbursement. If it is not, the payment waits and the reason is stated. The institution can always override.
That still requires: a scoped authorization tied to payee, amount, currency, obligation, policy version, evidence snapshot, issuer and expiry; integration with a treasury, bank or escrow system; financial invariants proved rather than tested, meaning no duplicate release, no release above authorized funding, no execution by an unauthorized issuer; a bounded fallback when evidence or services fail, so lawful payments are never held indefinitely; and a legal entity, insurance, an independent security audit and a willing payment partner.
Proof. A single payment in a controlled pilot where a delegated condition was checked, the result was correct, the override worked, and the full audit trail reproduces.
The honest distance. This is years and several institutions away, and it cannot begin until the layers above it are solid. Nothing on this list is close.
5. The constitutional question
SUNLIGHT's first principle is that every output is an indicator and never an allegation, and that the system never decides. A payment layer that holds money is the system acting. That is an amendment to the constitution, and it has to be argued openly rather than absorbed quietly.
It can be argued. If the institution writes the condition, delegates the check, and retains the override, then the institution is deciding and the software is executing a rule the institution already wrote. That is defensible.
But two things change permanently the day it is built.
The cost of being wrong changes hands. Today a false positive costs an analyst an hour. With a payment hold it costs a supplier their payroll, and in a poor country it can destroy a real business. Every tolerance, every threshold, every unassessable state is now load-bearing in a way it has never been.
The system acquires enemies with a motive. Nobody games SUNLIGHT today because it holds nothing. The day it holds money, every party with something at stake has a reason to corrupt its inputs. The capture layer, the identity layer and the evidence gate become security surfaces, not just correctness surfaces.
The governance consequences are not optional. No performance fee on recovered funds, ever: a percentage gives the system a financial interest in its own findings, and every refusal built into it becomes arguable. Producer obligations bound at the contract, not funded from recoveries, because a fund financed by detected fraud shrinks as the system succeeds. And no sole authorship of the standards it is measured against.
The decision to build this layer should be taken explicitly, written down, and dated. It should not arrive as the next item on a list.
6. The order of work
Steps 1 and 2 are housekeeping and take days, not weeks, but nothing else is trustworthy until they are done. Step 3 is the real milestone: the day the watch notices a change nobody told it about, the system is a watch rather than an analyser. Steps 4, 5 and 6 are the substance of the thesis and can run in parallel once step 3 holds. Step 8 is what an institution will test first, and step 9 begins only after the decision in section 5 is taken and written down.
7. What would make this fail
Six failure modes, ordered by how likely they are rather than how dramatic.
Work keeps being lost. It has happened twice in three weeks, both times because code lived only in a sandbox. The rule is now written down. If it slips again, the project loses more to repetition than to any technical obstacle.
Scope outruns proof. The brief that prompted this plan describes payment control, binding policy and shared oversight while the watch has never captured a live source. Every layer built on an unproven one inherits its weakness invisibly.
A claim outruns its evidence again. The synthesized evaluation population was published for months as prosecuted cases. It was caught internally, which is to the project's credit, but the lesson is that an attractive number survives scrutiny for a long time. Any figure that leaves this project should trace to a run someone watched.
The sources close. Everything demonstrated so far depends on public data staying public and machine-readable. The arms register already refuses programmatic access, the treaty secretariat's reports sit behind a document application, and a portal can add a key requirement at any time.
The join turns out to be rare. Twenty organisations across two UK systems is a real result, but it is one country and one registry. If cited identifiers are not shared across systems in most places, the watch reads fragments rather than chains. That would itself be a finding worth publishing, but it would change what the system can claim.
The payment layer is built before the foundation holds. This is the one that would be fatal rather than merely costly. A hold placed on a real payment from an unproven identity resolution, in a country where a supplier cannot absorb a week's delay, is a harm the system caused, and no refusal written in a charter undoes it.
8. Decisions that cannot be deferred
Five. The first two are overdue and block work that is already queued.
The deployed instance. Running pre-fix code with no admission boundary. Recommendation made 26 October: preserve its state, take it offline, do not delete anything, and point the hosted branch at the verified commit or mark it superseded.
The optional interpretation path. It can emit unsupported prose beside real evidence, and the audit produced exactly that about a synthetic organisation. Recommendation: remove it from the shipped build. If kept, never in an institutional build, never stored with facts, never in an export.
Where the reference corpus lives. It is outside Git by choice, which is right, but its location exists in one person's memory and its absence already made the floor unverifiable once.
Whether to build the payment layer at all. Section 5 sets out what it costs. The decision should be explicit and dated, not inherited from a plan.
The legal and institutional shell. No entity, no founder agreement, no university IP determination, no security audit. Nothing institutional can proceed without these, and they take months of elapsed time rather than days of work, so starting them late is what delays everything else.
